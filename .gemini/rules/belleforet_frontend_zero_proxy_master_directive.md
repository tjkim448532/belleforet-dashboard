# 🏛️ 벨포레 대시보드 프론트엔드 무결성 절대 원칙 (Zero-Proxy & SSOT Master Directive)

앞으로 작성하거나 수정하는 모든 벨포레 대시보드 및 프론트엔드 코드는 아래의 데이터 무결성 헌법과 지정된 포맷/구조 규칙을 예외 없이 100% 준수해야 합니다. 프론트엔드는 백엔드의 데이터를 있는 그대로 투명하게 보여주는 '거울' 역할만 수행하며, 어떠한 경우에도 데이터를 클라이언트 단에서 임의로 가공, 추정, 보정하지 않습니다.

---

### 1. 프론트엔드 임의 조작 및 가짜 숫자 생성 절대 금지 (Zero-Proxy & No Smart Guessing)
- **임의 안분 금지**: 달력 날짜 비율(예: 주중 일수 5/7 등)을 곱해 주중/주말 데이터를 쪼개거나 생성하지 마십시오. 반드시 백엔드(SSOT) 실측 데이터를 그대로 사용합니다.
- **추론 및 승수 조작 금지**: 상품명(예: '2인승')이나 특정 키워드를 기반으로 `.includes()`나 정규식을 사용해 탑승 인원이나 방문객 수에 임의의 배수(*2)를 곱하지 마십시오.
- **단가 왜곡 금지**: 부대 매출(카트비, 식음료 등)이 섞인 총매출을 방문객 수로 나누어 '가짜 단가(그린피)'를 산출하지 마십시오.
- **키워드 기반 상태 날조 금지**: 대행사 이름('스마트스코어', '골프몬' 등)을 기반으로 시간대(1부/2부)를 유추하거나 하드코딩하지 마십시오. 매핑되지 않은 항목을 임의의 확률(예: OTA 85%)로 단정 짓지 마십시오.

---

### 2. 텍스트, 라벨, UI 시각화 정직성 원칙 (No Mockup & No Clamping)
- **명칭 왜곡 금지**: 매출 비율을 '가동률(Occ)'로 둔갑시키는 등, 데이터의 본질과 다른 라벨을 붙이지 마십시오. ('매출 강도' 등 정직한 명칭 사용)
- **고정 목업 금지**: 실제 데이터 결과값과 모순되는 하드코딩 텍스트(예: 점유율 35%인데 '과반 점유'로 고정 출력)를 사용하지 마십시오. 조건부 렌더링을 통해 데이터에 맞는 동적 텍스트만 출력합니다.
- **시각적 기만 금지**: 프로그레스 바(Progress Bar)나 차트 렌더링 시, 0%이거나 매출이 없는 항목에 대해 최소 너비(예: 3%, 10%)를 강제로 부여(`Math.max(10, ...)` 등)하지 마십시오. 0은 반드시 0으로 시각화합니다.

---

### 3. 폴백(Fallback) 및 예외 처리 원칙
- 백엔드 데이터가 누락되었거나 `null`, `undefined`인 경우, 임의의 계절성(예: 7월), 임의의 비율(예: 0.5)을 기본값으로 주입하지 마십시오.
- 데이터가 없을 경우 숫자 연산은 안전하게 0으로 귀결시키고, 텍스트는 `미분류`, `-`, 또는 빈 문자열을 반환하여 데이터가 없음을 명확히 인지할 수 있게 처리합니다.

---

### 4. 벨포레 대시보드 고정 서식 및 구조 규칙 (불변)
- **금액 표기 서식**: 매출 엔진 데이터 소환 시 **'₩' 기호는 절대 사용하지 않으며**, 반드시 3자리 콤마가 포함된 `#,##0` 서식(예: `1,250,000원` 또는 `formatRevenue(val)`)을 적용합니다.
- **계층 구조 병합**: 표(Table) 렌더링 시 반드시 8대 부서 계층별 셀 병합(대분류 → 영업장 → 티켓그룹) 규칙을 정확히 구현해야 합니다.
- **시각화 차트**: 대시보드 차트 구성 시 전체 및 레져 부문에 대한 데이터는 3D 파이 차트(전체/레져) 형태로 구현합니다.
- **검증 마스터 규칙**: 사전에 정의된 '검증마스터 구축 규칙'의 데이터 정합성 대조 프로세스를 코드 내에 반드시 준수하여 설계합니다.

---

### 5. 배포 전 무결성 검증 통과 의무
작성된 모든 코드는 커밋 및 배포 전 무결성 검증 스크립트(`scripts/integrity-check.cjs`)의 Rule 1~8(가짜 안분, 단가 왜곡, 목업 라벨, 키워드 휴리스틱, 탑승인원 배수 추정 금지 등)을 완벽히 통과할 수 있어야 합니다. 위 원칙에 위배되는 로직이 단 한 줄이라도 포함되어서는 안 됩니다.

---

### 6. 🚨 [Zero-Simulation] 클라이언트 임의 시뮬레이션 및 거짓 숫자 생성 영구 금지 (/learn SSOT)
- 사용자가 예상 강수량/적설량, 목표 성장률 등 특정 시뮬레이션 변수 대입을 요구하더라도, **백엔드 정규 마트 API가 구축되지 않은 상태에서 클라이언트 단독으로 임의의 강도 계수(`강수량 / 15mm`), 선형 공식, 사칙연산 곱셈을 합성하여 가짜 숫자를 만들어내는 행위를 영구 금지**합니다.
- 월별 계절성(Seasonality)이 극심한 리조트 특성상, **전년도 동월(LY) 실측 모수** 없이 전체 통평균을 기준으로 삼아 예상치를 조작하는 것은 명백한 거짓 숫자 생성입니다.
- 필요한 시뮬레이션 모델이 있다면 반드시 공식 문서(`backend_request.md`)를 통해 백엔드 팀에 정규 마트 API 신설을 요청하고, 백엔드 배포 전까지 어떠한 임의의 숫자도 화면에 노출하지 않습니다.
